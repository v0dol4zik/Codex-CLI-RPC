# Codex Discord Rich Presence — план проекта

## Статус выполнения

- [x] Каркас проекта и конфигурация.
- [x] Dependency-free Discord IPC client.
- [x] Обёртка Codex CLI с аргументами, exit code и сигналами.
- [x] Фоновое переподключение без сброса таймера.
- [x] Установщик и документация.
- [x] Unit- и интеграционные тесты.
- [x] Живой smoke test Rich Presence с пользовательским Discord Application ID.
- [x] Фоновый монитор уже запущенных процессов `codex`.
- [x] Автозапуск монитора через пользовательский systemd service.
- [x] Lock от дублирующихся RPC-клиентов.
- [x] Управление сервисом через `codex-rpc service ...`.
- [x] GitHub CI, security-документ и публичный README.

Живой smoke test и работающий сервис требуют Application ID, созданный владельцем Discord-аккаунта; Bot Token не используется.

## Цель

Создать локальную Linux-утилиту, которая показывает в Discord активность Codex и время текущей сессии. Фоновый монитор запускается вместе с пользовательской сессией, подключается к локальному Discord IPC, находит уже работающий или позже запущенный Codex и удаляет активность после его завершения.

## Результат первой версии

- Команда-обёртка `codex-rpc`, принимающая все аргументы Codex CLI без изменений.
- Discord Activity с текстом «Работаю в Codex» и таймером от начала сессии.
- Настройка через переменные окружения или конфигурационный файл.
- Запуск Codex даже при выключенном или недоступном Discord.
- Очистка Rich Presence после штатного выхода, `Ctrl+C` и сигналов завершения.
- Инструкция по установке, созданию Discord Application и диагностике.

## Архитектура

```text
пользователь → codex-rpc → Codex CLI
                    │
                    └──── Unix socket discord-ipc-N → Discord Desktop
```

Обёртка хранит время запуска, отправляет Discord команду `SET_ACTIVITY`, запускает дочерний процесс Codex и передаёт ему аргументы, окружение, терминал, сигналы и код возврата. Режим `--monitor` читает `/proc/<pid>/exe` и `/proc/<pid>/stat`, поэтому не меняет поведение обычного Codex и сохраняет фактическое время старта процесса. Bot Token и внешний сервер не нужны — достаточно публичного Discord Application ID.

## Этапы реализации

### 1. Каркас и конфигурация

- Создать Python-пакет, CLI entry point, тесты и документацию.
- Использовать Python 3 и прямое подключение к Discord IPC без обязательных сторонних библиотек.
- Поддержать параметры `DISCORD_CLIENT_ID`, путь к настоящему Codex, текст статуса и необязательные изображения Rich Presence.
- Не сохранять токены или персональные данные.

### 2. Discord IPC

- Искать сокеты `discord-ipc-0..9` в `XDG_RUNTIME_DIR`, `/run/user/<uid>` и совместимых каталогах.
- Реализовать framing протокола Discord IPC и handshake версии 1.
- Отправлять `SET_ACTIVITY` с Unix timestamp в `timestamps.start`.
- Обрабатывать таймауты, повреждённые ответы и отсутствие Discord без падения Codex.

### 3. Управление Codex CLI

- Передавать все аргументы `codex-rpc` настоящему бинарнику `codex`.
- Исключить рекурсию, если пользователь добавит alias `codex=codex-rpc`.
- Сохранить интерактивные stdin/stdout/stderr и управление терминалом.
- Передавать сигналы дочернему процессу и возвращать его exit code.
- Гарантированно очищать активность при завершении.

### 4. Устойчивость

- Повторно подключаться, если Discord запустился позже или был перезапущен.
- Сохранять исходный timestamp при переподключении, чтобы таймер не сбрасывался.
- Не мешать работе Codex при любой ошибке RPC.
- Для v1 при нескольких сессиях показывать последнюю запущенную; отдельно задокументировать это ограничение.
- Запускать монитор как пользовательский systemd service и автоматически перезапускать его после сбоя.
- Не допускать одновременное владение Presence wrapper-ом и monitor-ом.
- Проверять Python, shell и systemd unit в CI перед публикацией.

### 5. Установка и UX

- Добавить установщик в `~/.local/bin`.
- Предложить shell alias/function без замены оригинального бинарника Codex.
- Добавить команды `--check`, `--version` и понятный диагностический вывод.
- Описать создание Discord Application и добавление image assets.

### 6. Тестирование

- Unit-тесты кодирования и декодирования IPC-фреймов.
- Тесты поиска сокета и обработки некорректных ответов.
- Интеграционный тест с поддельным Unix-сокетом Discord.
- Тест передачи аргументов, сигналов и exit code фиктивному процессу Codex.
- Ручной smoke test: запуск, рост таймера, `Ctrl+C`, выключенный и перезапущенный Discord.

## Критерии готовности

1. `codex-rpc --version` запускает настоящий Codex и сохраняет его вывод и exit code.
2. При работающем Discord статус появляется не позднее чем через 5 секунд, таймер начинается с запуска сессии.
3. При выключенном Discord Codex запускается без заметной задержки и продолжает работать.
4. После закрытия Codex Rich Presence исчезает.
5. После перезапуска Discord статус восстанавливается без сброса таймера.
6. В проекте нет Bot Token, пользовательских данных и жёстко заданного UID.
7. Автоматические тесты и линтер проходят локально.
